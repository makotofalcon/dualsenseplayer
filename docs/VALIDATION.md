# 検証記録と実機受入試験

この文書はソフトウェアで確認した範囲と、展示機材での未実施項目を区別します。仕様書の同期値・停止時間・復帰時間・連続運転目標を達成済みとは扱いません。

## この環境での検証

- Debian 13 x86_64 / .NET SDK 10.0.403。
- WPFアプリ、Windows音声・HIDライブラリ、監視プログラムのReleaseビルド。
- xUnitでチャンネル分離、補正の符号、初回の前周抑止、1,000周のPCM境界、独立した読み取り、ミュート、上限、復帰フェード、時計追従、停止・シークの世代切り替えを検証。
- 設定破損・バックアップ復元・停止ラッチ・別PC復元・二重機器登録の拒否・監視の再起動上限を検証。
- 実際に生成したH.264 MOV/4ch PCM、MP4/4ch AAC-LCをFFmpeg 7.1.5でデコード。音声PTSの開始差、AAC尺、2ch・破損素材の拒否を検証。
- 映像を3周デコードし、フレームハッシュを比較。途中へのシーク後も周回境界のフレーム順が一致することを検証。
- 1本・2本・3本のプレイリストを実デコードし、解像度・fps・PCM/AACが異なる動画の順序、全体の周回、後半動画へのシーク後のフレームハッシュを検証。
- 動画ごとのch対応、音声・振動が同じ境界で切り替わること、補正が前後の動画や周回境界をまたぐこと、末尾の補間、振動全停止を検証。
- 再生順・重複配置・各動画の設定の保存復元、旧設定からの移行、PCM上限、先読み中の終了、次の動画を読み込めない場合のエラー表示を検証。

最新の件数・実行結果は `artifacts/validation.txt`（配布フォルダーでは `validation.txt`）に記録します。配布用FFmpegと同じ機能構成をLinuxでもビルドし、デコードテストへ使用した結果は `validation-minimal-decoder.txt` に記録します。配布用のWindows EXEはクロスビルド品です。このLinux環境ではWindows GUIと実機の入出力を実行していません。

## 展示機材で実施する項目

| ID | 手順 | 合格基準・記録 |
|---|---|---|
| AT-01 | channel-checkを再生し、通常L/Rと両台の振動L/Rを個別確認 | ch3/4が会場音声へ混ざらない。デコード順と保存した対応を記録 |
| AT-02 | MOV/PCM24とMP4/AAC、さらに本番書き出し素材で確認 | 先頭・末尾・実振動・ch順を比較 |
| AT-03 | sync-checkと光センサー・2台の振動センサー・通常音声を同一時計で30イベント以上記録 | 2台間 p95≤10ms/max≤20ms、映像対振動 p95≤30ms/max≤50ms、映像対通常音声 p95≤40ms/max≤60ms |
| AT-04 | 30秒のloop-checkを1,000周 | アプリ起因黒フレームなし、余分な停止≤1映像フレーム、連続波形の音声・振動断≤10ms |
| AT-05 | 本番動画24時間。開始/1h/8h/24hで同期測定 | 停止・クラッシュ・バッファ不足0、1h以降メモリ純増≤100MBで増加傾向なし |
| AT-06 | 各台10回、同時5回のUSB抜き差し | 残りを継続、現在位置で復帰、OS列挙完了からの時間を別記録 |
| AT-07 | 停止・シーク各20回。振動全停止中に再接続・異常再起動 | 旧波形なし、停止保持。正常時の振動全停止≤100msを実測 |
| AT-08 | 登録した通常音声とディスプレイを切断・復帰 | 通常音声の転送なし。表示先切断は全出力停止、復帰後先頭再開 |
| AT-09 | プレーヤーを強制終了・ハング | 旧プロセス終了後に復旧、二重再生なし、再起動上限と正常終了の維持、強制終了後の実振動停止 |
| AT-10 | 2ch・VFR・未対応コーデック・破損動画・壊れたJSON | 開始前拒否または設定待ち。振動の自動生成なし |
| AT-11 | ネットワーク無効・PC再起動・スリープ復帰 | 同梱物だけで運転、保存した自動開始と停止意思を維持 |
| AT-12 | 解像度・fps・ch対応が異なる3本を配置し、並べ替え・保存・再起動・選択動画からの再生・全体シークを実施 | 保存順どおりにA → B → C → Aと進み、各動画のch対応を維持。動画間と最後→先頭の映像・音声・振動の途切れを実測 |

`channel-check` は8秒で4経路を順に励振します。`sync-check` は30秒で毎秒のパルスと白フラッシュを同期させます。`loop-check` は30秒の連続正弦波で境界の断を確認します。各MOV/MP4を同梱し、生成スクリプトも公開しています。

## 既知の制約

実機PoCが完了するまで本番展示の受入済み版にはできません。特にWindowsのContainer IDによるHID/音声照合、共有4ch形式、HID初期化、機械的振動、ドライバー遅延はLinuxテストの対象外です。Windowsが必要な識別情報や4ch形式を公開しない組み合わせは、自動割り当てや2ch化をせず待機します。

映像はソフトウェアデコードとWPF WriteableBitmapで表示します。1080p60での描画負荷、次の動画の先読み負荷、動画間・ループ時の途切れは対象PCで測定してください。時計補正はソフトウェア上の出力時刻の推定で、ディスプレイやアクチュエーターの物理遅延を測定したものではありません。

実機記録にはPC・GPU・ディスプレイ・通常音声機器・DualSense型番/ファームウェア・USBポート/ハブ・Windowsビルド・素材ハッシュ・補正値・センサー位置・検出閾値を含めてください。ソフトウェアログだけで同期目標の検収を代用しないでください。
